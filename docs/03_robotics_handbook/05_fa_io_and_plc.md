# 05. 電気 I/O・FA通信（NPN / PNP の罠）

ソフトウェアエンジニアが実機配線で一番つまずきやすい **DC24V のデジタル I/O（DI/DO）** と **FA特有の極性（NPN / PNP）** の基礎です。

## 1. 「24V I/O（DI / DO）」とはどういうことか？
ラズパイや Arduino の GPIO が `0V / 3.3V〜5V` で動くのに対し、工場のロボット・PLC・センサ・電磁弁は **`0V (OFF) / DC24V (ON)` の電気信号（電線1本＝1ビットのON/OFF）** でやり取りします。

- **DI（Digital Input：入力）**：外部機器からロボットへ入ってくる信号
  - 例：`DI0` に DC24V が来たら「真空スイッチ ON（＝ボトルを吸えた）」、`DI1` が来たら「光電センサ反応（＝コンベア空き）」
- **DO（Digital Output：出力）**：ロボットから外部機器へ出す信号
  - 例：Python から `set_do(0, True)` を呼ぶと `DO0` から DC24V が出力され、真空電磁弁が開いて吸引が始まる
- **なぜ 24V なのか**：工場はモーターや電磁弁による電気ノイズが大きく配線も長いため、3.3V/5V ではノイズで誤動作します。**DC24V** を使うことでノイズ耐性を確保するのが FA の世界標準です。

---

## 2. 【超重要】NPN（シンク）と PNP（ソース）の違い
センサやロボットの仕様書に必ず出てくる言葉で、**日本のFA機器（キーエンス・オムロン等）は NPN が多く、海外製ロボット（欧州・中国系）は PNP が標準** のことが多いため、ここを間違えると信号が一切読めません。

| 方式 | 特徴（イメージ） | 主な地域・メーカー |
| --- | --- | --- |
| **PNP（ソース出力）** | 信号 ON のとき **+24V** が出力される（海外標準） | 欧州系・多くの中国系協働ロボット |
| **NPN（シンク出力）** | 信号 ON のとき **0V（GND）** に引き込む（日本標準） | 日本の PLC・日本メーカー製センサの多く |

- **対策**：
  - ロボットコントローラが PNP/NPN どちら対応（または配線で切り替え可能）かを事前確認する。
  - センサや電磁弁を買うときは**ロボットの極性に合わせる**（合わなければリレーを1個挟んで変換する）。

## 3. 電磁弁（誘導負荷）とサージ保護
- 真空吸引の電磁弁は内部にコイルが入っているため、OFF にした瞬間に高電圧の逆起電力（サージ）が発生する。
- **対策**：必ず**サージ保護（ダイオード・バリスタ）内蔵の電磁弁**を選び、ロボットの DO 出力や周辺 USB カメラの破損・フリーズを防ぐ。

## 4. Modbus（モドバス）とは何か？
工場の機器（PLC・ロボット・電動グリッパ・インバータ等）同士で数値をやり取りするための、**最も普及しているシンプルな産業用通信プロトコル**です。

- **2つの方式**：
  - **Modbus TCP**：Ethernet（LANケーブル / TCP/IP、ポート `502`）で通信。PC（Python の `pymodbus` 等）や PLC との通信はこちら。
  - **Modbus RTU**：RS-485（シリアル2本線）で通信。ロボット手先の電動グリッパや小型機器との接続でよく使われる。
- **通信の仕組み（ソフト屋向けイメージ）**：
  - REST API や JSON ではなく、**「相手機器のメモリ上にある配列（レジスタ番地）を直接 Read / Write する」** 仕組みです。
    - **Coil（コイル）**：1bit（ON/OFF）の配列（DI/DO の状態など）
    - **Holding Register（保持レジスタ）**：16bit整数（`0〜65535`）の配列（目標座標・品種番号・エラーコードなど）
  - 例：`Write Register(addr=100, val=1)` で起動、`Read Register(addr=200)` で現在のステータスを読む。
