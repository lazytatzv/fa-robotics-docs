# ビジョン・AI認識方針（Task 1：ボトル認識）

## 1. カメラは必要か？
**2階からランダムに落ちてくる状態から拾う場合、カメラは必須です。**
（機械的なガイドやパーツフィーダで完全に1列・同姿勢に整列できる場合は光電センサのみで済みますが、ボトル形状に若干のバラつきがある場合はカメラで位置・姿勢を認識する方が柔軟に対応できます。）

## 2. AI（YOLO等）は使うべきか？

**結論：使う価値は高いですが、「普通の物体検出（水平矩形）」だけではロボットは掴めません。**

ソフトウェアエンジニアが最初につまずきやすい点として、通常の YOLO（`x, y, w, h` のバウンディングボックス）では **「ボトルが何度傾いているか」「口（トップ）がどっちを向いているか」** が分からないため、コンベアに正しい向きで置けません。

### おすすめの認識アプローチ

| 手法 | 取れる情報 | メリット・向いているケース |
| --- | --- | --- |
| **YOLO-pose（キーポイント検出）** | ボトルの「口」と「底」の2点 | **◎ 最有力**。中心座標・傾き・上下の向きが一発で決まり、吸着点と置く向きを同時に計算できる |
| **YOLO-seg（インスタンスセグメンテーション）** | ボトル1本ごとの領域マスク | 重なりがある山積みでも「一番上に乗っているボトル」を抽出しやすい（マスクの主軸から傾きを算出） |
| **YOLO-OBB（回転矩形）** | 傾き付き矩形 | 傾きは取れるが、上下（口と底）の判別には別クラス分けや追加判定が必要 |
| **古典的画像処理（OpenCV等）** | 輪郭・重心・主軸 | 背景と色の差が大きく重なりがない場合に超高速。ただし透明ボトルや重なりには弱い |

## 3. 2Dカメラ vs 3Dカメラ（Depthは必要か？）

**結論：「1層に広げられるなら 2D（Depth不要）がベスト」「山積みのまま取るなら Depth が必要（ただし透明ボトルに注意）」です。**

| 条件 | Depth要否 | 理由と対策 |
| --- | --- | --- |
| **1層（重なりなし）に広げられる** | **不要（2DでOK）** | ボトルの高さ（Z）がほぼ一定になる。吸着パッド側に**バネ（バッファ機構）**を付ければ数mm〜1cmの高さズレは物理的に吸収できる。 |
| **山積み（2段・3段に重なる）** | **必要（3D / RGB-D）** | 上下の高さが分からないと、下のボトルを取りに行って上のボトルに衝突する／空振りする。 |

### ⚠️ 空ボトル特有の「Depthの罠」と Task 1 での対策方針
Task 1 では**「山積みになっている可能性が高い」「基本不透明だが、一部に色付き透明（半透明）がある」**という条件のため、以下の方針で設計・検証します。

1. **RGB-Dカメラ（RealSense / Orbbec 等）＋ RGB-AI のハイブリッド構成**
   - 基本が不透明ボトルであるため、数万〜10万円帯の RGB-D カメラでも主力のボトルは Depth が取れる見込みが高い。
   - **検出・向き判定（口と底）は RGB 画像（YOLO-pose / YOLO-seg）で行い**、検出領域内の有効な Depth 値から高さ `Z` を取得する。
2. **「色付き透明」ボトルへの実機テスト（最優先PoC）**
   - 色付き透明ボトルは顔料によって赤外線（Depthセンサの波長）を反射する場合と透過・欠損する場合がある。
   - まずは実物ボトルを机上に山積みにして撮影テストし、Depth が欠損しないか確認する。
   - もし一部が欠損する場合は、**「周辺の有効Depthから高さを補間する」「吸着パッドのバネストロークを長めに取り、真空スイッチ監視付きでゆっくり降下して接触吸着する」**等のソフト＋メカ工夫で吸収する。
3. **山積み対策（雪崩・衝突防止）**
   - 山が高すぎるとピッキング時に崩れたりアームが干渉したりするため、落下口にスロープや仕切りを設けて**「山を低く平準化（1〜2層程度）」**できると安定性が大きく上がる。

## 4. 具体的なカメラ選定の目安

- **2D構成の場合（推奨：数万円〜10万円前後）**
  - **グローバルシャッター方式の産業用2Dカメラ**（Basler、IDS、FLIR、HIKROBOT 等 ＋ Cマウントレンズ）
  - ※一般的なWebカメラ（ローリングシャッター）は、ボトルが転がっている瞬間を撮ると像が歪むため、工場導入時はグローバルシャッター＋固定焦点レンズが安心。
- **3D構成を試す場合（PoC向け：数万〜10万円前後）**
  - Intel RealSense（D405 / D435 / D455）や Orbbec（Gemini / Femto シリーズ）
  - ※導入前に**必ず実物のボトルを並べてDepthが欠損しないか**テストすること（透明ならラベル部分だけDepthを取る、等の工夫が要る）。

## 5. カメラ接続方式（IP/Ethernet vs USB）

**結論：PoC は手軽な「USB3」、工場本番はノイズと配線長に強い「Ethernet（PoE / GigE）」がおすすめです。**

> **注意：「防犯・監視用のIPカメラ（RTSP）」は非推奨**
> 一般的な監視用IPカメラは映像圧縮（H.264等）による遅延（数百ms〜1秒）や露光・ピントの自動変動があるため、ロボットピッキングには向きません。ここでいう「IP（Ethernet）接続」は、**産業用 GigE Vision カメラ**や **PoE対応 RGB-Dカメラ**を指します。

| 観点 | USB 3.x（RealSense等） | Ethernet / PoE（GigE / PoE RGB-D） |
| --- | --- | --- |
| **導入コスト・手軽さ** | **◎** 安価（3〜5万円台）で PC に挿すだけ | ○ やや高価（6〜15万円台）。PoEハブ/インジェクタ要 |
| **ケーブル長・取り回し** | △ 原則 2〜3m まで（延長は不安定になりやすい） | **◎** LANケーブル1本で 10m〜100m まで安定 |
| **工場ノイズ耐性（電磁弁等）** | △ 真空電磁弁のサージノイズで USB 切断が起きやすい | **◎** 絶縁性が高くノイズに強い |
| **物理的な抜けにくさ** | △ コネクタ固定が必須（ネジ止め対応機種推奨） | **◎** RJ45ラッチ（またはM12ロック）で抜けにくい |

### おすすめの使い分け
- **PoC（机上・社内テスト）**：USB3 の RGB-D カメラで素早くボトル認識・Depth検証を行う。
- **工場本番**：ケーブルが2〜3m以上になる・電磁弁が近くにある場合は、**PoE対応 RGB-D（Orbbec 等）** または **GigE Vision カメラ** を採用すると現場トラブルが激減する。
- ※もし本番でも USB3 を使う場合は、**ネジ止めロック付きケーブル・フェライトコア・外部給電USBハブ**を必ず併用する。

## 6. カメラ設置とキャリブレーションの注意点
- **設置方式**：
  - **Eye-to-Hand（固定カメラ）**：作業エリアの上方に固定。1回の撮影で全体を見渡せ、ロボット動作中も次のボトルを先読み計算できるため**タクト短縮に有利**。
  - **Eye-in-Hand（手先カメラ）**：アーム先端に搭載。近づいて高精度に見られるが、毎回撮影位置へ移動する時間がかかる。
- **座標変換**：
  - カメラのピクセル座標 `(u, v)` をロボットのベース座標 `(X, Y, Z)` に変換するため、**キャリブレーション（平面ホモグラフィ／Hand-Eyeキャリブレーション）** が必須になる。
