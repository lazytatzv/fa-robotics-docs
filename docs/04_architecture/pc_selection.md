# 制御PC選定ガイド（YOLO推論 ＋ ロボット制御）

Task 1（RGB-Dカメラ撮影 ＋ YOLO推論 ＋ 6軸協働ロボット制御）を Ubuntu Linux 上で安定稼働させるための PC 選定基準です。

## 1. 結論・おすすめ構成

| 導入フェーズ | おすすめ構成 | 概算価格帯 | ポイント |
| --- | --- | --- | --- |
| **PoC・社内検証** | 一般の x86_64 PC（RTX 3060/4060 搭載デスクトップやワークステーション） | 15〜25万円 | SDKやライブラリの互換性を気にせず最速で検証できる |
| **工場本番（第一候補）** | **x86_64 産業用PC（IPC）＋ NVIDIA GPU**（Advantech / Neousys / コンテック等） | 20〜40万円 | **x86_64 の互換性**と**工場の耐環境性（防塵・耐熱・24時間稼働）**を両立 |
| **工場本番（省スペース・低予算）** | **Jetson Orin NX / Nano 搭載の産業用エッジPC** | 10〜20万円 | ファンレス・小型・TensorRTでYOLOが高速。**※ARM64対応確認が必須** |

## 2. 具体的な推奨スペック目安（Intel / GHz / GPU / RAM）

| パーツ | 推奨スペック（本番・快適ライン） | 最低ライン（PoC） | 選定の理由・注意点 |
| --- | --- | --- | --- |
| **CPU メーカー** | **Intel（第12〜14世代 Core i5 / i7 相当）** | Intel / AMD どちらでも可 | 産業用PC（IPC）は Intel が主流。Ubuntu 上での NIC や USB ドライバの安定性・実績が最も高い |
| **コア数 / クロック** | **8コア以上 / Boost 4.0〜4.5GHz以上**（ベース 2.0〜3.0GHz帯） | 6コア / Boost 3.5GHz以上 | カメラ取得・点群処理・ROS 2・制御を並列実行。工場では最大GHzより**熱ダレ（サーマルスロットリング）しない冷却設計**が重要 |
| **GPU（AI推論）** | **NVIDIA RTX 3060 / 4060** または **RTX A2000 / 2000 Ada**（VRAM 8GB〜12GB） | RTX 3050 / Jetson Orin Nano (8GB) | YOLO-pose/seg は CPU の GHz より GPU の有無が圧倒的に効く（TensorRT 化で 5〜15ms/frame 程度） |
| **メモリ（RAM）** | **32GB**（DDR4 / DDR5） | 16GB | PyTorch/TensorRT ＋ RGB-D点群処理 ＋ ROS 2 ＋ Docker を同時起動すると 16GB では余裕がなくなる |
| **ストレージ** | **NVMe SSD 1TB** | SSD 512GB | エラー発生時の画像スナップショット・ログを自動保存する領域を確保 |
| **LAN（NIC）** | **Intel製 GbE / 2.5GbE × 2ポート以上** | 1GbE × 1〜2ポート | ロボット直結用と、PoEカメラ／保守用でネットワークを物理分離できる |

> **CPU と GPU の優先順位について**
> 画像認識（YOLO）を回す場合、**CPUを 5GHz のハイエンドにするよりも、CPUは Core i5 クラスに抑えて NVIDIA GPU（RTX系）を載せる方が、処理速度も安定性も圧倒的に高くなります。**
> ※ARM64（Jetson Orin NX 等）を選ぶ場合は、ロボットメーカーの SDK が ARM64 Linux に対応しているか事前確認が必須です。

## 3. PCは何台用意すべきか？

**結論：現場で動かす本番PCは「1台」で十分ですが、開発・保守・故障時バックアップまで含めると「現場本番1台 ＋ 開発/予備機1台 ＋ 現場作業用ノート1台」の体制が最も安全です。**

| 役割 | 台数 | 構成・用途 |
| --- | --- | --- |
| **① 現場本番用（制御PC）** | **1台** | 工場の制御盤・架台に常設（産業用IPC / Ubuntu）。カメラ取得・YOLO推論・ロボット制御をすべてこの1台で完結させる（処理分散でPCを2台に分けると通信・同期が複雑になるだけなので非推奨） |
| **② 開発・学習 兼 予備機** | **1台** | 社内での開発・YOLOモデル学習用。**本番機と同等スペック（できれば同型番IPC）**にしておくと、本番PC故障時にSSDやDockerイメージをそのまま載せ替えて即復旧（コールドスタンバイ）できる |
| **③ 現場立ち上げ・保守用ノート** | **1台** | 現場でのティーチング・SSH接続・ログ確認用。メーカーの初期設定ツールがWindows専用の場合に備え、Windows（またはデュアル環境）があると安心 |

> **なぜ「予備機」を意識すべきか？**
> 工場のラインが止まったとき、産業用PCの修理や再手配には数日〜数週間かかることがあります。平時は「社内開発・検証機」として使い、緊急時は「現場への差し替え予備機」にできる構成にしておくと、余計な遊休コストをかけずにリスクヘッジできます。

## 4. PCの電源電圧（AC100-240V / DC24V / 19V アダプタの選び方）

| 電源入力方式 | 主な該当PC | 工場本番への適性 | 設計・選定時のポイント |
| --- | --- | --- | --- |
| **DC24V 端子台<br/>（DC9〜36V等ワイド入力）** | ファンレス産業用IPC、Jetson Orin エッジPC | **◎ 最良** | 制御盤内の FA用 DC24V 電源からネジ止め端子台で直接給電でき、抜けず熱にも強い（※PC消費電力分の電源容量余裕を見ること） |
| **AC100-240V 内蔵電源** | 大型GPU（RTX 3060/4060等）搭載 IPC・ワークステーション | **○ 良好** | ATX 電源内蔵のため外付けアダプタ不要。制御盤の AC 系統から直接給電する |
| **DC19V 外付け ACアダプタ** | 民生用ミニPC（NUC等）、ゲーミングノートPC | **△ PoC向け**<br/>（本番は対策必須） | **PoC には手軽で最適**。ただし本番投入には「丸型DCジャックが振動で抜ける」「プラ製アダプタが盤内の熱で劣化しやすい」「復電自動起動がない機種がある」という弱点がある |

### やむを得ず 19V 機を本番で使う場合の必須対策
1. **DC ジャックの抜け防止**：ネジロック付きプラグを選ぶか、インシュロック（結束バンド）や固定金具で物理的に抜けないよう固定する。
2. **AC アダプタの固定と放熱**：制御盤内でブラブラさせず金属板に固定し、盤内温度が上がらないよう換気・放熱を確保する。
3. **BIOS 復電自動起動の事前テスト**：主電源を落として再投入したときに、PC の電源ボタンを押さずに自動起動するかを必ず実機テストする。

## 5. 工場導入で見落としがちなハード要件

1. **有線LANポートは「2系統」以上あると便利**
   - ポート1：ロボットコントローラと直結（固定IP、制御用）
   - ポート2：保守・SSH・ログ回収用（または PoEカメラ用）
2. **USB 3.x の安定性と抜け防止**
   - RealSense 等の USB3 カメラを使う場合、振動で抜けないようネジ止めロック付きポートや結束固定を行う。
3. **耐環境性（熱・粉塵・ファン故障）**
   - 家庭用・ゲーミングPCは工場の粉塵や夏場の高温（40℃近く）でファンが詰まり故障しやすい。本番はファンレスまたは防塵フィルタ付きの産業用PC（IPC）を選ぶ。
4. **復電時自動起動（BIOS：Power On after AC Power Loss）**
   - 工場の主電源・ブレーカーを落とした翌日、**電源を入れたら PC も自動起動して制御プログラムが立ち上がる**設定ができる機種を選ぶ。
